# 0.7.0：回归轻量记录

2026-10-31。用户决定移除内置 AI，专注信息填写、记录、UI、iPhone/Watch 同步与 Apple Health。

## 已实施范围

- 移除 App/OptionalAI.swift、MealRecognition.swift、TextMealRecognition.swift 及专用模型 smoke 脚本；没有 Foundation Models import 或模型调用入口。
- ProductEditor 保留 OCR 和离线规则解析，移除 AI 开关、进度、超时任务与模型诊断入口。
- MealEditor 仅以规则整理明确输入的名称/份量，营养手动填写；照片只作临时核对参考。旧照片 Intent 类型保持，标题和行为改为手动记录。
- 添加中英文外部工具指引和通用提示词 ShareLink，不接入账号、API 或自动传送用户数据。
- 通知错误从模型错误类型解耦；移除模型不影响通知授权与提醒。
- 保留 Codable 历史模型字段、估算来源、冻结事件与写入计划；不迁移或重写历史健康样本。
- Watch 沿用现有轻量 UI、产品投影、稳定请求 ID 和 iPhone 单一写入通道。

## 验证

本轮 167 项核心测试通过（0 失败）；OpenIntake scheme 的无签名 iOS 构建通过，包含 iPhone、Watch、iPhone Widget 和 Watch 表盘组件目标。中英文 strings 通过 plutil 检查；公开文件检查 135 项、0 个发现。未在本轮覆盖安装真机，也未新增真实健康样本。新增回归覆盖无需 AI 的文字餐食 → 手动营养 → 确认 → 待同步事件，以及历史估算快照解码与来源保留。现有失败重试、撤销与 Watch 防重测试继续运行。

## 真机验收

1. 建立一个手动标签模板，保存后检查没有摄入事件；实际记录时核对样本值、时间及来源。
2. 扫描标签：应直接得到规则草稿，没有 AI 开关、模型等待或超时；核对错误内容后保存。
3. 输入含 g 和 mL 的餐食：名称和份量可整理，营养留空；全未知时不得显示同步成功。填写已知值并确认后记录。
4. 外部指引只分享通用提示词，不附带产品资料或照片；返回后手动填写。
5. Watch 记录一次饮水/产品，手机仅出现一次事件；断开再连接不得翻倍。HealthKit 写入及权限验证在 iPhone 检查。
6. 检查历史记录仍可读取、来源不变；撤销、恢复、重试与通知设置继续可用。

文档中的历史 AI 研究和模型测试不能作为 0.7.0 的在用功能说明。尚未解决的通用营养合理性校验缺口见历史审计；本次收敛不宣称完成其全部 P0–P3 工作。
