# 隐私设计

- 无账号、服务器、分析、广告 SDK、崩溃上报或网络请求代码。
- 拍摄页仅在内存交给 Vision OCR；不保存包装照片到本 App 文件或相册。系统文档相机内部行为由 iOS 管理。
- OCR 原文、全部成分（包括不支持写入健康的成分）、包含关系、映射选择、产品、确认记录、OCR 行坐标/置信度、语言能力快照、可选 AI 结构化草稿、独立规则草稿和摄入审计账本保存在 Application Support/OpenIntake/library.json。
- iOS 资料库目录及文件使用 complete file protection；完整 JSON 原子替换，明确排除系统备份。不是额外自行实现的密码库；安全性依赖系统设备保护及用户解锁。
- 不开启 CloudKit 或 iCloud 容器。Apple 健康的数据同步由用户的系统健康/iCloud 设置管理，和本 App 的 Zero Server 分开。
- 首次前台启动请求39种营养类型写入权限，用户可逐项允许或拒绝；之后权限页允许用户主动选择类型。不请求其他来源健康数据的读权限，不申请临床记录或药物权限。0.3.1保存及撤销后只按本App来源和事件同步ID查询自己的样本以核验，不作广泛健康读取。
- Foundation Models 使用 SystemLanguageModel.default 本机结构化生成；默认允许，用户可在扫描界面关闭“使用本机 AI”，设置保存在设备。模型 available 且语言检查通过时，拍摄完成或用户点击重新解析会调用；否则明确回退保守规则。没有额外模型文件、付费 API 或云端提供者。模型是否可用由设备、地区、系统设置及模型准备状态决定。
- Siri/快捷指令会接触用户主动选择的产品实体及名称，受系统功能隐私设置控制；不把这个系统入口描述为完全脱离操作系统的隐私边界。
- 卸载 App 会移除本地产品及账本，但不会自动删除已写入 Apple 健康的样本。先在 App 撤销，或在 Apple 健康的数据来源管理中删除本 App 数据。
- 移除产品只移除模板，历史快照为撤销及来源追踪继续保留。撤销事件保留审计内容。MVP 暂无资料库导出、导入或全量本地清除界面；见路线图。

未来引入任何外部数据库、BYOK 或自部署模型时，需先让用户主动选择，并说明发出的数据、目标域名和存储行为。不得默默降级到网络模型。

项目包含不追踪、不收集外传数据及空 Required Reason API 列表的 PrivacyInfo.xcprivacy；发布前需按最终 SDK/API 用法重新审核。

本项目不提供摄入推荐，不根据健康数据进行广告、画像或数据出售。提交 issue 时使用虚构标签，避免上传个人健康记录。

`--semantic-pipeline-audit` 仅在 Debug 构建可用：处理代码内合成标签，不保存产品或摄入，不调用 HealthKit；输出能力及验证计数，不输出个人标签。仓库 OCR 集成测试仅绘制合成文字；本次本机诊断另经用户授权处理其提供的截图文字区域，截图没有加入仓库。

0.3.0 增加餐食照片草稿：Shortcuts的图片输入或相机照片仅存在当前草稿内存中，不保存图像或文件URL，不上传网络。仅调用可用的本机SystemLanguageModel视觉能力。用户校准并确认后才保存食物、实际克数及估算来源快照。饮水目标和提醒偏好保存在本机UserDefaults；本机通知由系统调度，不使用APNs服务器。饮水统计只覆盖本App账本。

### 本机提醒

提醒计划只保存在本机UserDefaults与iOS通知中心，不经过服务器。通知内容可含补充剂产品名称，锁屏是否预览由系统设置控制。提醒授权与健康授权独立；提醒/测试通知不会创建摄入事件。

0.3.3 将完整可解码的模型原始 JSON 与对应输入批次保留在本机产品证据中，便于检查错误；不自动上传、不将真实标签写入调试日志。公开仓库只含公开标签文字回归，不含用户截图或个人摄入记录。用户删除资料时沿用本机产品/事件快照生命周期；历史事件仍保留当时资料用于同步和撤销审计。

0.3.5 权限恢复：已关闭通知使用官方系统设置URL，健康权限读取逐类型写入状态及是否需要授权请求，提供人工修改路径。App不能自行打开已拒绝的健康权限。权限选择勾选与系统授权状态分开呈现。恢复权限不自动记录、补写或启用新的提醒计划。

0.4.0 手动饮料/食品和食盐记录仅保存本机，无图片上传、外部营养查询或模型调用。糖钠统计只汇总本App账本，不增加健康读取权限。新增manualEstimate来源用于人工分食/普通盐换算，不冒充AI或测量值。饮料体积不自动作为饮水健康样本写入。模板及实际事件保持独立生命周期。

## 小组件共享边界

0.5.0新增同一开发团队App Group，只有产品ID、名称、数量单位及常用数量的可丢弃投影供扩展选择。文件使用首次解锁前保护（completeFileProtectionUntilFirstUserAuthentication）和原子更新，允许系统在首次解锁后读取这一最小投影；私有摄入账本不迁移、保护方式不变；不包含摄入历史、原始OCR、照片或AI解析。产品名称和小组件数量标记privacySensitive，系统环境决定隐藏效果。主账本位置未改变，不由扩展写入；系统动作打开主App重新验证和记录。无额外网络或账号。

文字餐食也仅由本机模型处理，无网络Provider。原始输入只在编辑内存，确认后的事件明细保留逐项来源引用和估算来源，帮助用户追踪；不会发布到共享小组件。取消草稿不产生摄入。
