# 餐食确认修复 · 0.5.2 / build 13

## 实际根因

旧 `MealEditor` 的 `.onChange(of: JSONEncoder().encode(items))` 每次渲染都会重新编码。默认 JSONEncoder 不保证对象键顺序，所以值完全相同也可能产生不同 Data，并执行 `accepted = false`。本机使用同一结构值编码 100 次出现 2 种字节序列，重现了错误的变化判断。Toggle 原 binding 是正常的；问题在确认后渲染触发的重置。旧页面还通过 `try? MealValidation.product` 静默禁用提交，没有显示具体失败原因。

## 修改点

- `Sources/IntakeCore/MealReview.swift`：`MealReviewState` 直接对 Equatable 餐食值比较。`setAccepted` 校验份量；`submissionIssues` 给出原因；`beginSubmission` 在启动异步任务前占用提交状态；`validateRequest` 拒绝已入账草稿再次提交（包括跨重启、超过一分钟或已撤销的原草稿）。`finishAnalysis` 拒绝已取消、过期的异步回调。
- `App/MealEditor.swift`：Toggle 绑定上述状态，移除 JSON 监听，初始化仅执行一次。缺名称、缺份量、非法值、文字已改变、正在识别、无已知营养和未确认均明确显示。`submit` 复用健康队列。`analyze` 在已有文字或条目时只附加参考图片，保留份量和确认状态，不猜骨头/包装/容器重量。
- `Sources/IntakeCore/DailyIntake.swift`：MealPortion 增加可选 `milliliters/per100mL`，兼容旧克数快照。MealValidation 根据各自基准汇总，绝不把 mL 作为 g；未知营养省略，已有值保留来源。全部营养未知时允许确认份量，但不允许伪造健康同步。
- `Sources/IntakeCore/TextMeal.swift`：保留 g/kg/mL/L 明确份量；原文只有一个明确数量时，不因模型漏填 quantityQuote 而丢失。模型遗漏的独立原文段落保留为无营养估算的待核对条目；中文逗号和非数字间英文逗号支持分项。重叠原文引用不得重复累计。
- `App/TextMealRecognition.swift`：仅调整餐食 Schema，区分每100g和每100mL，要求保留饮料。无法解码的营养类型/单位仍排除；错误基准的估算清空，原始饮用量保留。
- `App/IntakeStore.swift`：`logMeal` 检查草稿请求身份后调用原 `log`，保持本地 outbox → HealthKit 写入/核验 → 重试与撤销路径。
- `App/OpenIntakeApp.swift`：仅增加 DEBUG + Simulator 的餐食 UI 测试入口；正常用户路径无测试数据。

未修改补充剂 OCR、标签语义模型、成分映射或 HealthKit 适配器。

## 饮料是否被遗漏

旧 TextMealValidation 不会仅因为单位是 mL 删除整行，但只预填 g/kg；饮料即使返回也成为缺克数条目，导致整个餐食无法提交。另有确定的遗漏缺口：若模型未返回某项，或该项证据校验被过滤，剩余结果会直接替换完整原文草稿，没有完整性补回。

没有当次真机的模型原始返回，不能确定截图中缺失的饮料具体是在生成阶段还是证据过滤阶段丢失，也不能排除截图只展示部分列表。回归测试刻意只返回炒面和排骨，旧路径只留下两项；修复后补回「维他柠檬茶 500 mL」，营养未知、明确提示待核对。完整模型返回则保持三项和各自估算来源。模型解码整体失败时，完整原文草稿仍在。

补回按明确分隔符划分的原文项目，不是通用语义完整性证明；复杂叙述仍需逐项核对。AI 营养估算不保证真实配方准确，尤其含骨肉类要由用户校准实际可食部分。本次没有升级照片识别率。

## iPhone 验收

1. 更新后使用题述三项文本并开启本机 AI；逐项核对 450 g、500 mL、500 g。排骨如包含骨头，应改成实际吃下的可食重量。
2. 未知营养保持空缺；核对可用估算，开启确认。滚动、展开营养明细后开关保持，关闭开关后提交禁用。
3. 改任一实际份量，确认自动取消；缺失/0/负数应明确说明原因。停止 AI 后手动确认，稍候不应被旧结果覆盖。
4. 已输入文字或校准份量后拍照，原食物、数量和确认不能被照片替换；照片不能推断可食重量。
5. 仅实际摄入时确认记录一次，在同步中心查看结果，再核对 Apple 健康对应样本与来源。部分项目无营养时只写已知小计，不能称为完整总量。
6. 拒绝某项权限时应保留本地待同步；授权后重试不重复。撤销应删除本事件的对应健康样本，误撤销可恢复。
