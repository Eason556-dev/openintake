# 系统小组件与快捷指令（0.5.1）

> 版本说明（2026-10-31）：0.7.0 已移除内置模型与自动餐食营养估算。本文涉及 AI 的内容为历史实现或计划；当前行为见 [轻量记录版本](LIGHTWEIGHT_RECORDING.md)。

保持离线、无账号、AI可选。系统动作是实际摄入入口，不把扫描、拍照或保存产品当摄入。所有记录由主App单一写入者处理，沿用持久化待同步队列、逐类型健康授权、样本核验、失败重试、重复检测、撤销与恢复。

## 使用系统小组件

安装后先打开一次OpenIntake，并保存确认好的产品。长按iPhone主屏幕 → 编辑 → 添加小组件 → 搜索OpenIntake。

- **快速饮水**：小号，150／250mL按钮；实际喝下后点选。
- **常用产品**：小号或中号。在App里选择产品与实际数量，点更新小组件。小号与中号共用设置。饮料用mL，食品用g，补充剂用产品所显示的粒或份。数量留空时使用产品常用量（包装mL/g或默认粒／份），记录按钮明确显示实际数值；也可自行指定。旧版产品组件需重加，并在App重新设置数量。

点击记录按钮会打开App并执行记录，可能要求解锁或健康授权。返回的消息必须区分“已写入并核验”和“本机待重试”。没有可用产品、产品已删除或数量无效时不会写入；产品单位已改变时会要求重新选择，不能把mL误当g。产品含量按当前确认版本计算，事件创建后仍保留不可变快照。

列表不显示时先解锁并打开App，在App里重新选产品。WidgetKit刷新由系统调度，不能承诺实时刷新。小组件不显示健康全局统计或摄入历史；常用产品名称及数量标记privacySensitive。锁屏小组件、控制中心控件和watchOS尚未加入。

## 快捷动作

App首页“小组件与快捷指令”提供可执行的原生选择表单、系统ShortcutsLink和配置说明。ShortcutsLink用于管理动作，不冒充可运行工作流。快捷指令中新建流程 → 添加操作 → 搜索OpenIntake：

| 动作 | 参数及单位 | 行为 |
| --- | --- | --- |
| 记录饮水 | 实际毫升数 | 打开App记录纯水；不是饮料容量 |
| 记录补充剂服用粒数 | 已确认产品、实际粒数 | 按已确认每份粒数换算；未确认粒数则使用按份动作 |
| 记录补充剂摄入（按份） | 已确认产品、实际份数 | 使用产品每份定义 |
| 记录饮料或食品实际数量 | 手动标签模板、实际mL／g | 按标签计算糖、钠等；未知仍未知，不自动计为水 |
| 识别餐食照片并确认摄入 | 系统拍照动作的照片输出 | iOS18+，打开校准草稿，确认后才记录；AI依当前系统和设备支持 |

统一流程、饮水、补充剂粒数、饮料食品作为四个App Shortcuts自动发现；按份及照片动作可在自定义快捷指令中添加。内部小组件动作隐藏，避免与这些用户动作重复。

### 三个可直接配置的工作流

1. **我喝了250mL水**：添加OpenIntake“记录饮水”，固定250。运行一次即记录实际喝水，失败时查看App同步中心，不要反复新建事件。
2. **记录今日保健品／饮料**：添加对应产品动作，选择已确认的产品。把实际数量固定为常用值，或设为“每次询问”。按真实服用／喝下数量运行；补充剂2粒不等于2份，饮料330表示330mL。
3. **拍照记录餐食**：系统“拍照” → OpenIntake“识别餐食照片并确认摄入”，照片参数引用上一动作的结果 → 在App校准实际份量并确认。识别失败不会自动生成营养；不保证所有餐食可被本机模型准确识别。

在支持操作按钮的iPhone中：设置 → 操作按钮 → 快捷指令 → 选择自己创建的流程。Siri可运行用户命名的快捷指令。不会代替用户修改系统按钮或自动化设置；系统语言、权限和锁定状态可能影响运行。

## 扩展与签名

工程生成器现在包含OpenIntakeWidgets目标、主App嵌入依赖、共享App Intent源和App Groups entitlement。iOS最低17；不是新增服务器或模型。

App私有library.json位置不变。App Group只发布可丢弃的产品选项（ID、名称、单位及常用数量），不共享账本、OCR照片／文本、AI输出、API密钥或健康授权状态。文件原子写入、completeFileProtectionUntilFirstUserAuthentication（只对这份最小产品投影，供首次解锁后的系统展示；私有账本保护不变）；扩展只读。动作打开主App后重新验证产品，扩展不能直接写账本或HealthKit。共享投影失败不会回滚真实账本，失效ID不能被记录。

开发者需在Xcode给主App与OpenIntakeWidgets选择同一开发团队，启用同一App Group；主App继续保留HealthKit。默认group.org.openintake.shared仅为开源示例，Fork应在忽略的Config/Local.xcconfig设置自己的OPENINTAKE_APP_GROUP，并在开发者账号注册／配置。两目标的Info与entitlement使用同一构建变量。签名配置是否可用取决于开发团队和Apple账号能力；无签名编译不证明真机App Group授权可用。不要将个人团队ID或profile提交到仓库。

官方依据：[WidgetKit交互](https://developer.apple.com/documentation/widgetkit/adding-interactivity-to-widgets-and-live-activities)、[配置App Groups](https://developer.apple.com/documentation/xcode/configuring-app-groups)、[App Intents运行模式](https://developer.apple.com/documentation/appintents/configuring-the-runtime-behavior-of-your-app-intents)。当前用iOS17已有openAppWhenRun实现前台单写入者，App与扩展都包含同一意图类型。扩展意外执行时返回明确错误，不生成虚假成功。

## 真机验收

只用真实摄入进行健康写入验收。首次在Xcode确认两目标签名和App Group后安装；打开App保存产品，再添加两种小组件。验证配置不产生事件，记录正确数量、类型和时间，健康来源为OpenIntake。分别测试App前台、后台、强制退出后和锁定时的动作；锁定时应解锁或明确失败，不能悄悄丢记录。关闭对应健康写入权限时保留待同步，开启后重试不重复。快速重复点击应触发重复保护；撤销与恢复应处理对应健康样本。编辑或删除产品后测试旧小组件，单位变化应要求重新配置。拍照流程停在草稿和取消时均不得产生摄入。

未把无签名模拟器、核心mock或元数据检查当成真机HealthKit、Siri语音或操作按钮成功证明。

## 0.5.1统一可执行工作流

系统快捷指令直接运行OpenIntake“选择并记录摄入”App Shortcut；或新建自己的快捷指令，只放一个同名动作。无需把水、产品、照片顺序串联。该动作使用官方requestDisambiguation/requestValue：选择喝水、补充剂按粒／份、饮料食品、文字餐食或拍照餐食；只询问所选分支需要的参数。可预填某个分支和数量做固定动作。取消选择／输入不产生记录。系统菜单及锁定状态仍需真机验收。

App内“选择并记录摄入”按钮打开实际可操作表单，不用Widget专用Button(intent:)冒充App运行按钮。缺少共享产品的组件也能打开这份表单。餐食草稿请求会先关闭指引或记录菜单，再呈现确认页，避免弹层遮挡。

文字餐食支持1至4000字，最多30项。本机Foundation Models（iOS26+且模型可用）返回逐项原文名称、证据、显式质量和每100g／100mL营养估算；独立验证拒绝虚构引用，排除非法单位／未知零值／重复营养项，并拒绝矛盾营养总量。用户写出的g/kg可以预填，碗／个／杯及mL不转换为克。源文本中实际重复的两份不被盲目合并。每项营养标为AI估算，未知不填零；核对实际可食用克数／饮用毫升数与估算并确认后聚合为一个含明细的摄入事件，走既有健康写入核验。确认不是证明营养估算准确；不能替代标签／数据库。文字／图片模型失败或关闭时仅保留可编辑原文，不猜测营养；没有已知营养时不会伪造成功。修改原文或重新识别会取消旧确认；已有文字或手动条目时，照片只附在草稿作参考，不覆盖份量。0.5.2 起饮料保留独立 mL 计量基准，模型遗漏的原文项目保留待核对，未知营养不伪造。

小组件新增真实预览、未选择时的首个产品、按包装常用量、读取失败的明确提示及记录入口；已选择但删除的产品不会悄悄替换为其他产品。小号／中号分别排版，中号增加其他摄入入口。未配置／缺App Group不再只是一块无可操作内容的区域；实际产品共享仍需正确签名，界面修复不能绕过系统权限。

## 最终产品组件配置方式

QA日志确认旧AppIntentConfiguration路径发生XPC linkAction解析失败，返回空视图；拆分配置意图后仍失败。本版最终移除该配置意图和专用实体查询，使用与饮水相同的StaticConfiguration和TimelineProvider。产品与数量改在App的“小组件与快捷指令”设置，点“更新小组件”。小号和中号共用设置，不支持每个组件分别配置。

新的产品组件kind为OpenIntakeFavorite；旧OpenIntakeProduct需移除并重新添加，饮水组件不受影响。未选产品时显示首个已确认产品，显式选择已删除的产品不会偷偷替换；单位改变后不复用旧单位自定义数量。App Group仅发布选中产品的ID、名称、单位与常用数量。共享不可用时显示原因与可执行记录菜单，不能绕过签名权限。
