# 验证与真机验收

## 自动化

执行 `swift test`。核心测试覆盖：

- g/mg/mcg 及半份换算。
- 未确认草稿不能记录；未知值不产生营养项；药品、NaN、无穷、负数、重复成分拦截。
- 中英文标签质量提取、%DV、IU、不等式、多数值、千分位及重复营养行保守处理。
- 一分钟去重边界、撤销状态、事件快照和稳定 syncID。
- JSON pending/deletionPending 持久化恢复、损坏文件、不可读路径及未来 schema 拒绝加载。
- 模拟写入部分失败后重试、删除部分失败后重试、已撤销事件不重新写入、拒绝权限不调用写入。

模拟 HealthKit 用字典实现 syncID 幂等，不验证 Apple 实际数据库行为。真实权限、重复投递、相机和 Siri 必须按下方设备流程验证。

编译：README 中的 `xcodebuild`。本机验证日志路径在工作时为 `/tmp/OpenIntake-build.log` 与 `/tmp/OpenIntake-tests.log`，不提交含个人路径的日志到仓库。Xcode App Intents 自然语言训练处理器可能报告无法归档 SSU artifacts；必须区分整体 BUILD SUCCEEDED 和运行时 Siri 索引是否成功，后者以设备实测为准。

## 必须在 iPhone 上执行

使用虚构手动产品或核对过的实际包装，先不要一次写入很多事件。

1. 安装签名 App，允许相机。扫描含 `Serving Size 2 capsules`、`Vitamin D 25 mcg`、`Calcium 250 mg` 的标签。确认候选及 OCR 原文。
2. 添加产品前检查 Apple 健康：扫描过程不能产生样本。保存按钮明确执行一次性确认；扫描不能产生摄入。
3. 保存「1 份 = 2 粒」，选择实际服用 1 粒。记录后健康中应为维生素 D 12.5 mcg、钙 125 mg，时间等于记录时间。
4. 再点相同份数，应在 60 秒窗口内阻止重复事件。不同份数不被无故拦截。
5. 撤销，检查本事件各营养样本都已移除；其他 App/其他事件不能受影响。
6. 拒绝一种营养写权限，记录应保留 pending，不显示已同步。到健康权限设置授权，再重试，核对所有类型只有一份样本。
7. 杀掉/重新打开 App，检查产品及 pending 事件保留。模拟写后未标记的中断，再重试确认无重复；模拟逐营养删除中断后重试确认没有残留。
8. 编辑产品含量并重新确认。历史事件应保留旧含量，新的记录使用新 revision。
9. 设置固定产品/粒数 Shortcuts；前台、冷启动及锁屏分别运行。确认解锁要求和授权显示。支持 Action Button 的 iPhone 上绑定该快捷指令并验收。
10. 关闭 Apple Intelligence，确认 OCR/手动/记录均可用。支持且已准备模型的 iPhone，开启本机 AI 后重新扫描，检查结构化草稿、来源标记和人工确认约束。
11. 拒绝相机/取消扫描、离线、VoiceOver、大字体、中文标签、反光/弯曲包装及两列营养表均做人工检查。

## 当前限制

- 已在 iOS 27.0 iPhone Air 模拟器安装、启动并查看首页；尚未执行完整 UI 自动化或真实设备验收。
- 最低系统兼容来自 availability 与部署目标检查，尚未在 iOS 17 真机运行。
- 当前是结构化 OCR + 可选端侧语义模型 + 原文验证；跨行需表格或可靠位置，复杂多基准表与化学形式可能待确认。模型生成及真实相机效果须人工验收；不会自动可靠辨别药品。
- 记录默认当前时间；历史时间补记与保留原时间纠错尚未提供。当前修改摄入采用撤销并重新记录。
- 记录列表显示最近 50 条，账本保留全部。尚无导出/导入/清除界面；移除产品仍保留事件快照。
- 去重只覆盖本 App 当前资料库，不能检测其他 App、重新安装或不同设备的重复摄入。
- 文件完整保护使锁屏访问不可用，Intent 因此使用前台 App。watchOS 独立操作未实现。
- Foundation Models 是可选文本草稿路径，真实模型输出尚未验收；无 guided generation，也不宣称营养准确率。
- 没有食品数据库、条形码解析、餐食估算、饮水 Intent、App Store 图标或商店发布配置。
- 本地文件排除备份，卸载会丢失产品资料；健康样本不会随卸载自动清除。

## Jamieson Omega-3 + Turmeric 回归验收

使用 [虚构测试文字](examples/jamieson-label.txt)，粘贴后点重新识别。应出现鱼油 834 mg、Omega-3 500 mg、EPA 300 mg、DHA 200 mg、姜黄提取物 20 mg、干燥草本等效量 1,000 mg；每份 1 粒，比例 50:1。核对 EPA/DHA 属于 Omega-3，后者属于鱼油；等效量不是额外摄入。首页不展示 HealthKit 技术字段。

1. 默认关闭宽泛映射，一次确认保存。记录 1 粒应保留六项明细、状态为仅本地，无健康权限请求。
2. 编辑并同意较宽泛分类，记录 3 粒。仅多不饱和脂肪应请求权限并写入 1.5 g；1 粒对应 0.5 g。不要在 60 秒去重窗口重复点同一粒数。
3. 本地三粒明细为 2,502 / 1,500 / 900 / 600 / 60 / 3,000 mg；不把这些数值相加。姜黄比例备注仍为 50:1。
4. 拒绝写入权限，记录必须持久化 pending；退出重开仍在。授权后重试，同事件不可重复写入；撤销仅删除该事件样本。
5. 添加 Vitamin D 25 mcg，可自动准确映射；IU、EPA、DHA、姜黄保持本地，不手动选择技术字段。

自动化包含 31 项测试，覆盖中英文案例、单粒/多粒/每份两粒、质量转换、父子去重、等效量排除、层级矛盾、旧数据兼容、冻结写入清单及持久化失败恢复。Apple 写入行为由协议 mock 验证；授权弹窗、Apple 实际样本及撤销仍须真机验收。

首页打开“Apple 健康营养类型完整清单”，确认系统版本及 39 项类型/单位检查。Jamieson 保存产品后若尚未同意宽泛映射，首页必须提示“尚待确认”并提供入口。确认页应在成分列表前显示开关及写入预览：开启后多不饱和脂肪 500 mg；关闭后说明仅本地，不能声称系统不支持。已有 localOnly 记录不得因产品开关改变被自动补写。

## Xcode 启动后白屏排查

先看 Xcode 是否为 Paused。如果 HomeView.body 文件断点在首页绘制前暂停，手机可只显示空白启动画面。禁用该断点（或 Cmd+Y 关闭断点），再 Continue；必要时 Stop 后重新 Run。断点是本机 xcuserdata 设置，已被 Git 忽略，不应提交到开源项目。若无调试器暂停仍白屏，再检查进程、崩溃日志及主线程调用栈，不将所有白屏归因于同一原因。

## 0.2.0 语义管道真机验收

1. 打开新叶子图标，新增产品。检查本机模型状态及语言能力清单；开启可选 AI，拍摄清晰成分表和每粒基准。不要点击首页记录作为扫描测试。
2. Jamieson 应显示每粒鱼油 834 mg、Omega-3 500 mg、EPA 300 mg、DHA 200 mg、姜黄 20 mg / 50:1、干草本等效 1,000 mg。建议成人每天两粒独立显示，不把每粒变成两粒。英法重复行合并；原文、位置及证据可在详情核对。
3. 检查缺失值、置信度不足或基准错字明确待确认；如每粒被识别为母粒，不应产生可写营养。人工修正并明确确认该成分后再保存。关闭 AI 后应显示规则草稿而非假称模型成功。
4. 开启 Omega-3 → 多不饱和脂肪的宽泛映射，预览每粒 500 mg；其他五项本地保留。保存产品后近期摄入列表不得增加事件。
5. **仅在实际服用后**记录实际粒数。1 粒对应健康多不饱和脂肪 0.5 g、2 粒对应 1 g。首次允许该类型写入；拒绝授权时仍保留 pending 本地事件，授权后重试不新增第二份同事件样本。
6. 撤销该事件，在 Apple 健康查看对应样本已删除。撤销失败应保持待撤销，重试后完成；不能只有本地状态变更。旧事件继续使用旧快照，不因重新扫描产品变更历史数量。
7. 换不同角度重新扫描、仅拍英语/中文区、同时拍英法区，各核对一次。复杂曲面/反光和模型生成准确率尚未建立真实照片统计，不能由自动测试替代。

开发者可运行 `DEVELOPER_DIR=<Xcode>/Contents/Developer scripts/test_vision.sh`：15 个绘制标签角度案例经真实 Vision API，准确解析与因已知 OCR 错字正确阻止写入分别报告。该测试在 macOS 上运行生产 OCR 适配器，不代表 iPhone 相机验收。

`DEVELOPER_DIR=<Xcode>/Contents/Developer scripts/test_semantic.sh` 运行真实本机模型与验证/补全流程，只处理内置合成标签。模型不可用会 SKIP；拒绝或未达到六项成分 / 单项 PUFA 500 mg 预期时返回失败，不能把它算作成功的 AI 解析。

7. 餐食原照片不进入本地JSON；只保留确认食物、估算来源、份量及事件快照。不会保存成补充剂模板。

## 营养写入权限入口验收

首页 → 营养写入权限（同步中心也可进入）。检查39项写入状态，选择所需类型并申请，确认系统授权表出现尚未决定的营养类型。没有未决定类型时不承诺系统再次弹窗；已拒绝请到Apple健康的App数据访问管理调整。授权状态使用HKHealthStore.authorizationStatus(for:)核对的是写入权限，不推断读取权限。

权限操作不创建摄入或样本。维生素C/钙产品确认后记录实际摄入，应请求对应两项并按含量写入。Omega-3宽泛映射未启用时应明确提示，不以申请权限代替映射确认。未知数量、不可换算单位和待核对项目不虚构权限或样本。历史仅本机事件不自动回填。

## 0.3.1 官方授权与真实样本核验

首次前台启动应请求39种营养写入，Apple官方页应列出多个营养项目；若系统已有选择，直接检查App权限页状态。用户自主选择并点击Allow。授权本身不保存健康样本。

记录一次实际摄入后，核对“已写入并核验 Apple 健康”，到健康App对应营养的“显示所有数据”核对数量、时间和来源。保存后查询缺失、数量错误或重复时必须保持待同步。撤销后应不再出现对应样本。旧版记录明确显示“旧版未做样本核验”。此时核验不监测用户之后在健康App手工删除的数据。

### 0.3.2 双语AI与通知真机验收

1. 添加产品，拍摄Jamieson英法双语成分区，观察段落进度并等待“自动整理完成”。每粒鱼油834mg、Omega-3 500mg、EPA300mg、DHA200mg、姜黄提取物20mg及干草本当量1000mg应正确关联；Posologie/Prendre/Fournissant不得成为单独成分。核对原文证据，保存不会记录摄入。
2. 再拍一张文字分列/跨行标签；不可靠的对应应待确认，不能显示猜测数值。停止等待或重新扫描后，旧结果不能覆盖新草稿。关闭AI仍应可离线核对保存。
3. 首页→通知与服用提醒→允许通知，自己在苹果官方窗口选择允许。5秒测试：前台观察横幅，再锁屏/后台重复测试。拒绝后页面应显示关闭并提供系统设置；返回App刷新状态。
4. 为一个已保存补充剂设置接下来几分钟的每日提醒并保存，等待实际通知。重复保存同一产品仅保留一个pending请求；关闭或移除产品后不再安排。此过程不得新增摄入事件。
5. 饮水目标与提醒中启用时段提醒，核对保存成功和pending数量；授权失败时不得声称提醒启用。专注模式可能影响实际展示。

自动化覆盖输入精简保留原文/ID、批次边界两行重叠、表格位置、批次键去冲突、英法去重及单次宽泛映射、连接词前缀过滤、提醒ID/时间/持久化结构；不以这些核心测试代替通知系统或实际瓶身照片验收。

## 0.3.4 撤销和恢复验收

104项核心测试通过，新增完成删除恢复、部分删除取消、部分恢复重试、权限拒绝、重复替代记录防护、本机成分及持久化兼容测试。首页正常记录没有内联撤销；左滑应显示撤销，滑到底不能自动执行。点击撤销后显示恢复入口，待删除时显示取消撤销并恢复。恢复必须保留时间、数量、成分快照和事件ID；饮水统计应随撤销/恢复变化。超过首页50条的旧记录可到同步中心恢复。

真机仅选择一条确实发生的摄入做撤销/恢复，核对 Apple 健康样本先删除、再恢复且不重复，原摄入时间和数值不变。模拟器和 mock 不能替代真实 HealthKit 验收。权限关闭时应保留待同步；重新授权和重试应恢复且不重复。

## 0.3.5 权限关闭后恢复验收

通知：首次未决定时点允许应出现官方窗口；拒绝或在系统关闭后回到App，入口应变成“重新开启通知（前往系统设置）”。点击使用官方 openNotificationSettingsURLString；打开失败退回 App 设置，再失败显示手动路径。返回后核对状态/横幅/声音，重新保存需要的提醒，再用5秒测试验收前台和锁屏送达。已授权时按钮用于检查/调整，不重复请求授权。

健康：列表勾选仅代表选入申请，实际权限显示在名称下方。关闭一个营养写入类型后返回，状态应显示未允许；再次申请时先用 statusForAuthorizationRequest 判断是否会弹窗，不需要申请而含已拒绝类型时显示恢复步骤。Apple 健康→个人头像→App／数据访问权限→OpenIntake 开启需要类型，返回App自动刷新；也可手动刷新。授权操作不应创建摄入。选择未申请类型时仍可请求官方窗口。

无签名模拟器无法完整验证HealthKit授权；官方设置URL可能仅唤起设置而不定位目标页，因此App常驻手动路径。系统设置修改与真机通知送达必须实际验收，不能用构建或pending队列代替。
